# claude-code-active-rules

Claude Code の MOD「効いているルール」（active-rules）です。
MOD は、Claude Code の画面に、自分で作った部品を足す仕組みです。

いま文脈（コンテキスト）に読み込まれているルールを、1本ずつの表で見るペインを開きます。ペインを開いている間、表は5秒ごとに新しくなります。
ルールは、`.claude/rules` のフォルダーに置く `.md` のファイルです。

| 列 | 中身 |
|---|---|
| 分類 | ファイル名の先頭の【 】の中。例「書き方」 |
| 番号 | 分類の次の番号。例「03」 |
| P | ファイルの先頭に `paths` があるルールの印。`paths` は、ルールが効く場所を限定する条件 |
| 名前 | ファイル名から、【分類】、番号、`_P_`、`.md` を除いた部分 |
| 行数 | ファイルの行数 |
| 文字数 | ファイルの文字数（先頭の `paths` の部分と改行を含む） |
| トークン | そのファイルが文脈で使っている、推定のトークン数 |

表の最後の行は合計です。ルールの本数と、行数、文字数、トークンの合計を出します。
表の下には、ルールと CLAUDE.md の長さと書き方についての、Anthropic の公式の記述を出します。出典も付けます。

表に出すのは、ルールのうち、いま文脈に読み込まれているものだけです。
読み込まれているかは、Claude Code の文脈の内訳（/context と同じ形の内訳）に、そのファイルがあるかで決めます。
`paths` の無いルールは、セッションの始めに読み込まれるので、始めから表に出ます。
`paths` のあるルール（場所限定のルール）は、条件に合うファイルを Claude が扱い、そのルールが読み込まれてから表に出ます。

トークンは、Claude Code が手元で見積もった数です。トークンを数える API は呼びません。そのため、/context の数とずれることがあります。

Claude が Read、Edit、Write などのツールでファイルを触ると、そのファイルで効く場所限定のルールを toast で知らせます。
toast は、画面の右上に数秒だけ出る小さな知らせです。例えば「このファイルで効くルール 【書き方】_03_P」と出ます。
toast は、MOD が `paths` の条件を、触ったファイルのパスに照らして出します。Claude Code が実際に読み込むかとは、ずれることがあります。読み込まれたかは、表で確かめられます。

ファイル名が「【分類】_番号_名前.md」の形でなくても、フォルダーの直下の `.md` なら表に出ます。
【分類】が無いファイルは、分類と番号の欄が空になり、名前の欄にファイル名（`.md` を除く）をそのまま出します。例えば `README.md` は「README」と出ます。
【分類】があって番号が無いファイルは、番号の欄だけが空になります。
P の欄は、ファイル名の `_P_` ではなく、ファイルの先頭に `paths` があるかで決まります。
toast には「【分類】_番号_P」の短い呼び名を出します。番号の無いルールは、ファイル名のまま出します。

## 入れ方

Claude Code のターミナルのセッションで、次の1行を打ちます。

```
/plugin install active-rules --marketplace hatohato-lab/claude-code-active-rules
```

マーケットプレイスを足すかを聞かれたら `y` を押し、入れる範囲（scope）を Enter で選びます。

シェルからは、次の1行です。

```
claude plugin install active-rules --marketplace hatohato-lab/claude-code-active-rules
```

デスクトップアプリでは、入力欄の横の + から Plugins を開き、Add marketplace に `hatohato-lab/claude-code-active-rules` を入れてから、Add plugin で入れます。

クローンして使う場合は、フォルダーを指定して Claude Code を起動します。

```
git clone https://github.com/hatohato-lab/claude-code-active-rules
claude --plugin-dir claude-code-active-rules/active-rules
```

入れたあとも、ペインは自分からは開きません。`/rules` を打つと開きます。閉じたあとも、`/rules` で開き直せます。
`/rules` は、Claude が答えている途中でも、すぐに動きます。
ペインを置けない画面では、`/rules` の答えに、同じ表を文字で出します。

## 設定

設定は次の2つです。

| 設定 | 中身 |
|---|---|
| `rulesDir` | ルールの `.md` が入っているフォルダーの絶対パスです。初期値は空です。空のときは、セッションの作業フォルダーの `.claude/rules` を読み、作業フォルダーを基準に `paths` の条件を照らします。指定したときは、そのフォルダーの2つ上（`.claude/rules` なら、その上のフォルダー）を基準にします |
| `toasts` | ファイルを触ったときに、効く場所限定のルールを toast で知らせるかの切り替えです。初期値は `true`（知らせる）です。切っても、ペインはそのまま使えます |

## 必要なもの

- Claude Code 2.1.300 以降が要ります
- ほかに入れるものはありません。Python などの外のプログラムは動かしません
- 動作を確かめたのは Windows です。Linux は、GitHub Actions（ubuntu-latest）で、テストとマーケットプレイスからの入れ方を確かめています

## 気を付けること

- 読むのは、ルールのフォルダーの直下の `.md` と、Claude Code の文脈の内訳だけです。ルールのファイルは書き換えません
- 書くのは、MOD のフォルダーの `起動記録.txt` だけです。セッションが始まるたびに、版と時刻の1行に書き直します
- モデルも、トークンを数える API も呼ばないので、使用量はかかりません
- toast は、同じルールの組み合わせなら10分に1回までです。6秒ほどで消えます。会話にも AI にも、何も足しません
- 表に出るのは、1つのフォルダーの直下のルールだけです。サブフォルダーの中のルール、CLAUDE.md、ほかのフォルダーのルール（例えば `~/.claude/rules`）は出ません
- ペインを閉じている間は、ルールのフォルダーも文脈の内訳も読み直しません。セッションの途中で足したルールを toast の判定に入れるには、`/rules` を打ちます
